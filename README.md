# SURVEY_TOOLKIT OS v2.2.2 (PWA Edition)

เว็บแอปพลิเคชันคำนวณงานสำรวจ (COGO & Alignment Transformation) สไตล์ **1-bit Monochrome Desktop** ออกแบบมาเพื่อการทำงานหน้างานแบบ **Offline-First 100%** รองรับการติดตั้งลงหน้าจอมือถือ (PWA) และสามารถซิงค์ข้อมูลหมุดควบคุม (`ControlPoints`) กับประวัติการคำนวณ (`SurveyLog`) เข้ากับฐานข้อมูล **Google Sheets** อัตโนมัติเมื่อกลับมามีสัญญาณอินเทอร์เน็ต

---

## ระบบพิกัดและข้อกำหนดการคำนวณ (Coordinate Conventions)

1. **ระบบทิศทาง (Azimuth):** มุม $0^\circ$ เริ่มต้นที่แกน $+Y$ (ทิศเหนือ / North) และวนตามเข็มนาฬิกา ($0^\circ$ ถึง $360^\circ$)
2. **ระบบแนวเส้นทาง (Alignment System):**
   - **Chainage:** วิ่งตามแนวแกน $+Y$ ของแนวเส้นทาง (ไปข้างหน้าเป็น $+$, ถอยหลังเป็น $-$)
   - **Offset:** วิ่งตั้งฉากตามแนวแกน $X$ (ด้านขวาของแนวเส้นทางเป็น $+$, ด้านซ้ายเป็น $-$)

## โมดูลการคำนวณทั้งหมด (6 Modules)

| รหัสโมดูล | ชื่อแอป | รายละเอียดการทำงาน |
| :--- | :--- | :--- |
| **01** | **INVERSE** | คำนวณระยะราบ (Horizontal Distance), มุมอะซิมุท (DMS) และค่าต่างพิกัด $\Delta N, \Delta E$ ระหว่างจุด 2 จุด พร้อมปุ่มสลับจุด (`SWAP`) |
| **02** | **POLAR** | คำนวณพิกัดจุดเป้าหมาย ($N_2, E_2$) จากจุดตั้งกล้อง มุมอะซิมุท (DMS) และระยะราบ (สิทธิ์ `ADMIN` สามารถกด `+ SAVE BM` เพื่อบันทึกเป็นหมุดหลักฐานใหม่ได้ทันที) |
| **03** | **DEV CHECK** | ตรวจสอบค่าคลาดเคลื่อนแนวราบเทียบกับพิกัดออกแบบ แตกค่าเป็น **Chainage** และ **Offset** ตามมุม Azimuth ของแนวเส้นทาง พร้อมเทียบค่าเผื่อยอมรับได้ (`PASS` / `OVER!`) |
| **04** | **GLO -> LOC** | แปลงพิกัดฉากสากล ($N, E$) เป็นพิกัดแนวเส้นทาง ($\text{Chainage}, \text{Offset}$) รองรับการกำหนดแกน $+Y$ ทั้งแบบพิกัดอ้างอิง (`COORD`) และมุมอะซิมุท (`AZIMUTH`) |
| **05** | **LOC -> GLO** | แปลงค่าพิกัดแนวเส้นทาง ($\text{Chainage}, \text{Offset}$) กลับเป็นพิกัดฉากสากล ($N, E$) พร้อมระบบซิงค์ค่า Origin และทิศทางแกนร่วมกับโมดูล 04 อัตโนมัติ |
| **06** | **SET OUT** | คำนวณมุมราบเปิดตามเข็มนาฬิกาจากจุดธงหลัง ($\text{HA CW from BS}$), มุมอะซิมุท และระยะราบสำหรับงานวางผังด้วยกล้อง Total Station |

## คุณสมบัติเด่นและระบบความปลอดภัย

- **ทำงาน Offline 100%:** แคชไฟล์หน้าเว็บทั้งหมดลงเครื่องด้วย Service Worker (`sw.js`) สามารถเปิดใช้งานในพื้นที่อับสัญญาณได้เต็มรูปแบบ
- **Offline Queue & Auto Sync:** เมื่อกด `SAVE LOG` ขณะไม่มีสัญญาณ ระบบจะเก็บรายการไว้ใน `localStorage` และแสดงจำนวนค้างส่งบนแถบเมนู (`[SYNC:N]`) เพื่อส่งขึ้น Google Sheets ทันทีที่กลับมาออนไลน์
- **ระบบความปลอดภัยฝั่ง Backend (`Code.gs`):**
  - เข้ารหัสรหัสผ่านด้วย SHA-256 (Salt + Pepper จำนวน $1,000$ รอบ)
  - จำกัดจำนวนครั้งในการ Login ผิดพลาด (ล็อกชั่วคราวเมื่อผิดเกิน $5$ ครั้ง)
  - แยกสิทธิ์ผู้ใช้งานระหว่าง `ADMIN` (จัดการหมุด `[BM]` และเปิดดู Google Sheet ได้) และ `FIELD` (คำนวณและบันทึก Log หน้างาน)
  - ป้องกัน Formula Injection บน Google Sheets และป้องกัน XSS ฝั่งหน้าเว็บ

## โครงสร้างไฟล์ในโปรเจกต์

### 1. ฝั่ง Frontend PWA (โฮสต์บน GitHub Pages)
- `index.html` — หน้าจอหลัก โลจิกการคำนวณทั้งหมด และระบบจัดการคิวออฟไลน์
- `manifest.json` — ไฟล์ตั้งค่า Progressive Web App สำหรับติดตั้งลงหน้าจอโฮมสกรีน
- `sw.js` — Service Worker สำหรับแคชไฟล์แอปพลิเคชันให้เปิดใช้งานได้โดยไม่ต้องใช้อินเทอร์เน็ต
- `icon.svg` — ไอคอนแอปพลิเคชันแบบเวกเตอร์ 1-bit Monochrome
- `README.md` — เอกสารคู่มือโปรเจกต์

### 2. ฝั่ง Backend (โฮสต์บน Google Apps Script)
- `Code.gs` — เชื่อมต่อฐานข้อมูล Google Sheets (`Users`, `ControlPoints`, `SurveyLog`) และรับส่งข้อมูลผ่าน Web App API (`doPost`)

## ขั้นตอนการติดตั้งและเริ่มต้นใช้งาน

### ขั้นตอนที่ 1: ตั้งค่าฐานข้อมูล Google Sheets & Apps Script
1. สร้างไฟล์ Google Sheet ใหม่ (พิมพ์ `sheets.new` บนเบราว์เซอร์) และตั้งชื่อไฟล์ เช่น `SURVEY_TOOLKIT_DB`
2. ไปที่เมนู **ส่วนขยาย (Extensions) > Apps Script** วางโค้ด `Code.gs` แล้วกดบันทึก
3. เลือกฟังก์ชัน `setupDatabase` บนแถบเครื่องมือด้านบนแล้วกด **เรียกใช้ (Run)** เพื่อสร้างชีต `Users`, `ControlPoints`, `SurveyLog` และรับรหัสผ่านเริ่มต้นของ `admin` และ `survey01` ในหน้าต่าง Execution Log
4. กดปุ่ม **ทำให้ใช้งานได้ (Deploy) > การทำให้ใช้งานได้รายการใหม่ (New deployment)** เลือกประเภท **เว็บแอป (Web app)** ตั้งค่า **ดำเนินการในฐานะ:** `ฉัน (Me)` และ **ผู้ที่มีสิทธิ์เข้าถึง:** `ทุกคน (Anyone)` จากนั้นคัดลอกลิงก์ที่ลงท้ายด้วย `/exec` เก็บไว้

### ขั้นตอนที่ 2: เปิดใช้งาน GitHub Pages
1. อัปโหลดไฟล์ Frontend ทั้งหมด (`index.html`, `manifest.json`, `sw.js`, `icon.svg`, `README.md`) ไว้ที่ระดับโฟลเดอร์นอกสุด (Root) ของ Repository
2. ไปที่ **Settings > Pages** เลือก Branch `main` โฟลเดอร์ `/ (root)` แล้วกด **Save** เพื่อรับลิงก์ HTTPS ของตัวแอป

### ขั้นตอนที่ 3: ติดตั้งลงมือถือหน้างาน
1. เปิดลิงก์ GitHub Pages บนมือถือ (Chrome สำหรับ Android หรือ Safari สำหรับ iOS)
2. วางลิงก์ `/exec` จากขั้นตอนที่ 1 ในช่อง **GAS WEB APP URL** กรอก Username / Password แล้วกด `= LOGIN & SYNC` เพื่อดึงข้อมูลหมุดควบคุม `[BM]` เก็บลงเครื่อง
3. กดเมนูของเบราว์เซอร์แล้วเลือก **Add to Home Screen (เพิ่มลงหน้าจอหลัก)** เพื่อใช้งานในโหมดแอปเต็มหน้าจอได้ทันทีแม้ปิดอินเทอร์เน็ต

## การอัปเดตเวอร์ชันในอนาคต

หากมีการแก้ไขโค้ดในไฟล์ `index.html` และอัปโหลดขึ้น GitHub ให้ปรับเลขเวอร์ชันของตัวแปร `CACHE_NAME` ในบรรทัดแรกของไฟล์ `sw.js` (เช่น เปลี่ยนจาก `survey-toolkit-pwa-v2.2` เป็น `v2.3`) เพื่อให้เครื่องหน้างานดาวน์โหลดเวอร์ชันล่าสุดไปอัปเดตให้อัตโนมัติเมื่อเชื่อมต่ออินเทอร์เน็ต
